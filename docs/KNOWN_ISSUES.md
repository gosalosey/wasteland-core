# Known issues and limitations

| ID | Area | Description | Status |
|---|---|---|---|
| K-1 | Core / platform | Functions passed through exports arrive as FiveM function-reference *tables* (with `__call`), not Lua functions. The registry handles this. | **Verified at runtime 2026-10-10 (R1.1)** |
| K-2 | Core / platform | Runtime finding (R1.7, 0.1.0): restarting a resource makes FiveM stop the resources that depend on it, and does **not** start them again. Fixed in 0.1.1 for `restart wasteland_core` (a process-lifetime convar). Generalised in 0.2.0 to every module resource (for example `restart wasteland_database` brings `wasteland_players` back). Resources an admin stopped earlier are left alone. Setting: `framework.restartModulesAfterCoreRestart`. | Fixed; re-run R1.7 and R2.16 |
| K-3 | Lifecycle | Graceful shutdown covers resource stops and txAdmin-announced restarts/shutdowns. A killed process (crash, closing the window, `taskkill`) runs no shutdown, so changes since the last periodic save (at most `players.saveIntervalSeconds`) are lost. | By design (platform limitation) |
| K-4 | Config | Config changes to a running framework are validated by `config reload` but applied only on restart (except when recovering from config_error). | By design |
| K-5 | Tests | The Windows branch of the static "dead file" check had only run on Linux. | **Verified on Windows 2026-10-10** (Lua 5.4.6) |
| K-6 | Logging | Logs go to the server console (which txAdmin captures). There is no separate log file because FiveM's `SaveResourceFile` cannot append. | By design |
| K-7 | Admin | Player-issued admin commands show output in F8 only. wasteland_admin will add an in-game panel. | Planned M10 |
| K-8 | Database | MySQL/MariaDB commit DDL (CREATE/ALTER/DROP) implicitly. A migration that fails part-way can leave its earlier DDL applied. Mitigation: one idempotent DDL statement per migration (documented and followed by all framework migrations). | By design (database limitation) |
| K-9 | Database | A write that **timed out** (`database.queryTimeoutMs`) may still have been applied by the database. The caller is told it failed, and a late answer is logged as a warning. Framework writes are idempotent (absolute values and upserts) so a retry is safe. Module authors must do the same. | By design |
| K-10 | Players | After `restart wasteland_players`, characters are reloaded after `players.restoreDelayMs` (1 s) so the final saves of the previous instance land first. A database slower than that could serve a slightly older save. | Mitigated; verify R2.15 |
| K-11 | Players | Saved positions use server-side `GetEntityCoords(GetPlayerPed(src))`, which needs **OneSync**. Without it, positions stay at the last known value (the default spawn for new characters). | Check at runtime (R2.9) |
| K-12 | Players | Since 3A the character select screen (wasteland_ui) is the interface; the chat command `/character` remains as a fallback. The CFX `basic-gamemode`/`spawnmanager` still spawn the player first; selecting a character then moves them to its saved position. Death and respawn still use spawnmanager (survival rules arrive in Milestone 4). | Interim, planned M3/M4 |
| K-13 | Players | FiveM commands cannot be unregistered. The `/character` command name is registered once per resource start, so changing `players.commandName` needs `restart wasteland_players`, not just a module re-init. | By design |
| K-14 | Tests | The real-database test backend (`tests/lib/mariadbcli.lua`) runs the real SQL on MariaDB but imitates oxmysql's result typing. DATETIME values differ (string versus epoch ms), so the framework never reads DATETIME columns directly (it uses `UNIX_TIMESTAMP()`). The in-game tests (R2.x) verify the real driver. | By design |
| K-15 | Players | Until a character is loaded the client holds the player (frozen, invisible, no collision). This is a client-side convenience, not security: server-side gameplay modules must still check `IsCharacterLoaded(source)`. | Mitigated in 3A |
| K-16 | Players / platform | Runtime finding (R2.5, 2026-10-10): `deferrals.done(nil)` **rejects** the connection with "Unknown error"; FiveM only accepts `done()` with no argument. The players module passed `nil` on success, so every join was refused (the account row was still written). Fixed in players 0.1.1; the test mock now behaves like FiveM. | Fixed; re-run R2.5 |
| K-17 | UI / tests | Client Lua (camera, ped natives, NUI focus) and screen rendering cannot run outside the game. They are syntax-checked and their pure logic is unit-tested (Node), but their behaviour is only verified by the R3.x in-game steps. | By design (platform) |
| K-18 | Appearance | The server cannot know how many clothing/hair styles exist (client game data). It checks bounds and allowed slots; the client clamps to real counts before applying. A tampered client can only choose styles that exist anyway. | By design |
| K-19 | Appearance | Characters created before 3A have no look; the creator opens for them on their next load. | Expected |
| K-20 | Appearance | `spawnmanager` replaces the model on every respawn; the look is re-applied on `playerSpawned`. Death and respawn rules arrive in Milestone 4. | Interim, planned M4 |
| K-21 | Inventory | Weapons were not items. | Fixed (weapons 0.1.0) |
| K-22 | Inventory | The `naked` component values (what an empty clothing slot shows) differ between game builds; the shipped values are the common freemode ones and must be checked in-game (R4.9). | Verify at runtime |
| K-23 | Inventory | Hotbar keys 1-5 are also GTA's weapon-category keys. Harmless while there are no weapons; rebind in Key Bindings if needed. | By design for now |
| K-24 | Inventory | If the database keeps refusing one queued change while it is reachable (a permanent error, not an outage), that change is dropped after 10 attempts with an error so later changes are not blocked forever. | By design; investigate any such log line |
| K-25 | Inventory | Drops and stash distance checks use server-side positions (OneSync). Without OneSync, dropping and searching are refused with a message. | Platform requirement |
| K-26 | Inventory | Runtime finding (R4.4, 2026-10-10): releasing a dragged item threw `Cannot read properties of null (reading 'grabX')`, so no drag ever completed. The drop target was computed after the drag state was cleared. Fixed. The inventory opens with TAB (owner's request); GTA's weapon wheel on TAB is disabled every frame. | Fixed; re-run R4.4 |
| K-27 | Survival | Clients estimated the air temperature from their own (unsynced) weather and clock. Since wasteland_world, everyone has the server's clock and weather, so temperatures agree. | Fixed (world 0.1.0) |
| K-28 | Survival | Deaths and world damage are reported by the client (GTA health lives on the client). A cheating client could fake its own death (losing its own items) or hide damage (avoiding its own bleeding); neither affects other players. Server-side checks against hits by zombies and players come with Milestone 5. | By design for now |
| K-29 | Survival | The survival client turns off spawnmanager's automatic respawn; death and respawn are handled by Wasteland. Stopping wasteland_survival turns autospawn back on. | By design |
| K-30 | Survival | Animation, hand-prop and screen-effect names (eating, drinking, treating, infection blur, cold shake; props per consumable in survival.lua) are standard GTA ones but are only verified in-game (R5.5-R5.8). A missing model or animation is skipped and breaks nothing. | Verify at runtime |
| K-31 | World | The list of music emitters switched off (`shared/emitters.lua`) covers the well-known ones; a building that still plays music can be added by name in `world.lua` → `audio.emitters` (report it). | Verify at runtime (R6.2) |
| K-32 | Admin | Noclip and invisibility run on the admin's own client after the server allowed them. A modified client could do the same without the panel; anti-cheat for movement is out of scope for now. | By design |
| K-33 | Admin | Bans are by Rockstar license. A player with a second Rockstar account is a new account; identifier/hardware bans are not implemented. | By design for now |
| K-34 | Weapons | No attachments (scopes, suppressors, extended magazines) yet. | Later |
| K-35 | Weapons | The client counts shots (ammo going down) and melee hits and reports them once a second. The server never takes more ammo than the player has and logs reports above it, but a modified client could under-report shots (saving ammo and durability). | By design for now |
| K-36 | Weapons | Melee hits are counted from the game's damage events; on a server without NPCs they can only be checked on other players until zombies exist (5B). | Verify at runtime (R8.6) |
| K-37 | Server | Game build 3751 (mp2025_02) showed missing map parts on the owner's server; the server runs build 3570 (`sv_enforceGameBuild 3570`, in server.cfg.example). Nothing in the framework needs a newer build. | Workaround: build 3570 |
| K-38 | Images | The picture pack has no canned beans or peaches; they use canned peas and canned pears pictures (labels on the cans say PEAS and PEARS). Pants, hats and glasses use our own drawings (tools/images). Change `image` in inventory.lua or add a PNG to tools/images and run `python tools/import_images.py --custom-only`. | Cosmetic |
| K-39 | Zombies | The AI uses standard GTA tasks, a walking style (`move_m@drunk@verydrunk`), damage packs and an attack animation (`melee@unarmed@streamed_variations`, `plyr_takedown_front_slap`) that are only verified in-game; a missing animation skips the animation but not the hit. | Verify at runtime (R12.x) |
| K-40 | Zombies | The client that runs a zombie reports its hits and death. The server checks ownership, distance, cooldown and that a "dead" zombie is hurt, but a modified client could still make the zombies it owns hit within those limits, or never hit. | By design for now |
| K-41 | Zombies | No safe zones yet: zombies spawn everywhere players are, including inside interiors near players (spawn spots are on the ground nearest the chosen point). Safe zones come with zones in Milestone 7. | Planned M7 |
| K-42 | Zombies | Zombies are silent (no groans) because ambient voices are off; zombie sounds can be added later. | Later |
| K-43 | Target | Bags on the ground have no collision, so they are targeted through a small sphere where they lie (look at the ground at the bag). Scroll-wheel choosing uses the weapon-wheel controls, which are disabled while Left Alt is held. | Verify at runtime (R13.x) |
